The Surgical Additive Engine

json-api-builder-add-route

Surgically generates new route subtrees (e.g. v2/) and mounts them into parent routers with ESTree AST precision—without touching app.js or older versions (v1/).

$ cd api && npx --yes json-api-builder-add-route@latest v2.json
01 / The Mission

How This Repo Serves the Ecosystem

Why full project scaffolding is great on Day 1, but disastrous on Day 100.

The Greenfield Danger

When you run a full scaffolding generator, it generates app.js, setups middlewares, and builds directory trees. But once your API is live in production:

  • app.js has custom auth, rate-limiting, and error handlers.
  • v1/ endpoints are serving live production customers.
  • Re-running an orchestrator would clobber custom configs or wipe existing endpoints!
The Surgical Solution

json-api-builder-add-route runs localized directly inside your target router directory (e.g. api/).

  • It only creates the new route subtree folder (v2/).
  • It safely inspects and injects the route mount into api/routes.js via AST.
  • Zero touch to app.js and older versions (v1/).
02 / Technical Architecture

The AST Engine: Zero-Regex Manipulation

Why string regex replacement fails in JavaScript code modification, and how ESTree AST guarantees 100% syntactical safety.

1

Acorn ESTree Parsing

The existing parent router (routes.js) is read into memory and parsed using acorn.parse(source, { ecmaVersion: "latest", sourceType: "module" }). It creates a complete Abstract Syntax Tree of every statement.

2

Dynamic Router Detection

The AST scanner iterates through expressions to detect the router variable name. Whether the parent uses const routes = new Hono() or const app = new Hono(), it adapts automatically.

3

Idempotent Astring Synthesis

If v2 is already imported, it terminates without re-injecting. If missing, it constructs AST nodes for the import and routes.route("/v2", v2Routes), then serializes via astring.generate().

AST Node Structure Before and After Hooking ESTree Specification 
// 1. Existing api/routes.js (AST input)
import { Hono } from "hono";
import v1Routes from "./v1/routes.js";
const routes = new Hono();
routes.route("/v1", v1Routes);
export default routes;

// 2. AST Transformation injects new CallExpression before export
+ import v2Routes from "./v2/routes.js";
const routes = new Hono();
routes.route("/v1", v1Routes);
+ routes.route("/v2", v2Routes);
export default routes;
03 / Production Reality

Real-Time Enterprise Scenarios

How engineering teams use json-api-builder-add-route in daily production workflows.

Multi-Version API Lifecycle

A healthcare app has 50,000 active mobile users on /api/v1/clinics. The product team needs a new schema for /api/v2/appointments. add-route provisions v2 without altering or reloading the v1 runtime logic.

Autonomous Feature Teams

Team Alpha owns appointments; Team Beta owns doctors. Both work on the same monorepo. Instead of merge conflicts inside huge monolithic router files, each team generates localized subtrees with clean automated AST mounting.

CI/CD Automated Route Deployments

When a database migration or OpenAPI schema updates in git, a GitHub Action runs npx json-api-builder-add-route to generate the fresh endpoints and commits the diff without human intervention.
