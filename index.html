The Architectural Story

Why JSON API Builder Exists

Modern web applications require REST APIs, but manual boilerplate—writing repetitive router files, setting up directory trees, wiring CRUD handlers, hooking parent routers, and configuring middlewares—slows development down and introduces human error.

Traditional full-stack scaffolders generate entire projects once, but once established, they cannot touch the code again without overwriting custom edits. JSON API Builder solves both phases of the software lifecycle with mathematical Unix elegance:

Phase 1: Zero to Live Server

When starting from an empty folder, json-api-builder-orchestrator conducts the entire pipeline in seconds. You provide mock JSON data; it delivers a running Hono HTTP server serving tested endpoints.

Phase 2: Surgical Evolution

When your application is already in production and you need to introduce v2, json-api-builder-add-route runs localized inside the router folder. Using AST code analysis, it mounts the new subtree into the parent router without touching app.js or v1.

Genesis vs. Evolution

Two dedicated tools for the two distinct moments in your API's life

GREENFIELD MODE

json-api-builder-orchestrator

Starts from scratch. Coordinates all 7 micro-stages in deterministic sequence: validates schemas, scaffolds folders, provisions files, compiles AST templates, binds Hono middleware, and starts the server.

# 1-Line NPX Greenfield Runner
npx json-api-builder-orchestrator
# Generated output
app.js, api/routes.js, api/v1/*, data/*, server on :3000
Orchestrator Docs & API Guide
ADDITIVE MODE

json-api-builder-add-route

Runs on existing codebases. Localized inside your router directory. Reads a small route spec (v2.json), generates only the new route subtree, and uses Acorn AST to mount it into the parent router.

# Localized Subtree Generator
cd api && npx json-api-builder-add-route v2.json
# Non-destructive impact
v2/ generated, parent routes.js AST hooked, app.js untouched
